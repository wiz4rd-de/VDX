# Decisions

Choices made where SPEC.md leaves room (§14) or is silent/contradictory. Each
entry: what, why, spec section.

## Engine (lead)

- **D-E1 Envelope rate formula uses ⌊qrate/4⌋.** AC-E4.1's `2^(qrate/4)` is read as `2^⌊qrate/4⌋`; only that matches R-E4's tick periods `2^(11 − (qrate >> 2))` and gate masks (the real-valued exponent would contradict R-E4). §7.1 R-E4, AC-E4.1.
- **D-E2 Hold lengths above rate 76 are not rescaled.** R-E4 says hold counts are rescaled from 44.1 kHz; AC-E4.4 requires `20 × (99 − r)` samples for rates 77 and 99. The acceptance criterion wins: only `statics[]` (rates 0–76) are rescaled by 49096/44100. Holds follow Dexed: the static rate includes the rate-scaling delta, and an attack segment to level 0 uses `statics/20`. R-E4, AC-E4.4.
- **D-E3 Attack jump at segment start.** "If L < 1716 when an attack segment begins, set L = 1716" is applied when the segment begins (not at its first tick); if the target is below 1716 the segment completes immediately, as Dexed does in the same update. R-E4.
- **D-E4 One engine-wide EG clock.** The tick counter `c` is shared by every envelope (hardware-like); in "render at host rate" a fractional accumulator issues 49096/hostRate clocks per host sample. R-E4, R-E1.
- **D-E5 Velocity reference is `velocity_data[50]` (= 240), not 239.** R-E5 writes `velocity_data[v >> 1] − 239`, which makes velocity 100 16 counts louder than KVS 0 at KVS 7; AC-E5.2 and R-E5's own "velocity 100 is the 0 dB reference" require ±1 count. The acceptance criterion wins: the reference is the table entry for velocity 100, so velocity 100 is exactly 0 at every KVS. R-E5, AC-E5.2.
- **D-E6 LFO frequency equals the Dexed `lfoSource[]` table exactly.** Dexed's `lfo.cc` multiplies the table by `4437500000·N/fs`, which runs 3.3 % faster than the Hz values in its own table (and than R-E7's "0.0625 Hz … 49.3 Hz"). AC-E7.1 requires the period within ±2 % of the table, so the ratio is `2^32·N/fs`. Everything else in `lfo.cc` is ported as is (per-instance units instead of statics). R-E7, AC-E7.1.
- **D-E7 Algorithms 4 and 6 use true chain feedback in both modes.** MSFA's `fm_core.cc` only implements self-feedback (`(flags & 0xc0) == 0xc0`), although its table marks OP4/OP5 as `FB_OUT`. R-E8's explicit "OP6←OP4 and OP6←OP5" is implemented with a per-sample loop over the chain; the feedback formula is R-E8's. R-E8.
- **D-E8 Modern carrier scaling is applied to each carrier's gain.** "Carrier 1/C as a linear multiply" is applied to the carrier operator's gain (round(65536/C)), so a carrier's feedback path sees the same level as in Mk I, where `carrierAtt` is inside the kernel. R-E14, R-E3.
- **D-E9 A masked-off operator is silent immediately in both modes** (Modern gain 0, no ramp); its envelope and phase keep running. R-E3.
- **D-E10 Controllers use integer range scaling** `cc × range / 100` instead of MSFA's float `cc × (0.01 × range)`; identical except at float rounding edges, and deterministic across platforms. R-E13.
- **D-E11 Libm-free signal path.** Detune (`exp`), MSFA's AM curve (`exp`), portamento rates and host-rate phase tables use `core/fm/detmath.h` (series built from IEEE +,−,×,÷ only), so the DAC tap is bit-identical on every OS and in WASM. MSFA's `Sin`/`Exp2` tables are generated once by MSFA's own init. §14.
- **D-E12 Idle voices.** A released voice (not held by key or sustain) becomes idle when every carrier envelope has settled at a level ≤ 512 counts (where the Mk I kernel output is exactly zero). Idle voices score +4 for allocation and are not rendered. R-E11.
- **D-E13 Portamento.** Rate is R-E12's `2100 × 2^(−0.062 × time)` semitones/s for both plain glide and glissando (Dexed's slower glissando rate is not used); glissando rounds the glide offset to the nearest semitone. Poly FOLLOW retunes voices held only by sustain to the new note and glides them there; mono FULL TIME glides from the current pitch even on non-legato notes. R-E12.
- **D-E14 Pitch bend with step.** Bend = round((bend/8192 × 12) / step) × step semitones (range treated as 12); without step `bend × range × 2^11 / 12` (MSFA). R-E6.
- **D-E15 AC-E3.3 RMS steps are checked where the Mk I output resolves them.** R-E3's operator output is 14-bit (`exptab >> shift`), and the reference test voice (algorithm 32) adds a 6-carrier attenuation of 2.58 octaves inside the kernel, so at OL < ~60 the 1 kHz tone is only a few LSB and its RMS cannot resolve ±0.05 dB. R-E3's formulas are exact (KICKOFF), so the test checks: the internal level for every OL (LUT below 20, exactly 32 counts = 0.7526 dB per step from 20 to 99), RMS steps of 0.75 ± 0.05 dB wherever the peak output is ≥ 32 LSB (OL ≥ 64), and non-decreasing RMS below. R-E3, AC-E3.3.
- **D-E16 AC-E3.1 random voices.** Carriers OL 85–99, modulators OL 40–80 (the AC allows ≤ 80), coarse 1–4, FB 0. Below OL 40 a modulator's 14-bit Mk I output has fewer than 5 bits, and its sidebands then differ from Modern's 24-bit kernel by more than 1 dB as a property of R-E3, not an error. AC-E3.1.
- **D-E17 AC-E8.2 uses OP6.** No algorithm gives OP1 a feedback loop (FB_IN is on OP2–OP6 only), so the test voice's lone sounding operator is OP6 in algorithm 32, which is that algorithm's feedback carrier. AC-E8.2.
- **D-E18 Output-stage order.** Engine output (DAC filter or `/2^27`) → resampler → master-volume gain → hard clip, so the clip is the last operation at the host rate. R-E10.
- **D-E19 Timing of MIDI and latency.** A MIDI message stamped with host sample h is applied at the start of the internal 64-sample block containing h·49096/hostRate; a block is rendered in the `render()` call in which its end passes, so results do not depend on the host block size. `latencySamples()` = one internal block at the host rate + the resampler's look-ahead (`getInLenBeforeOutStart`) + 1, or 64 without the resampler. Commands posted before `render()` are applied at its start; `render(…, 0)` returns immediately. R-E1, R-E15, AC-E1.1, AC-E15.3.
- **D-E20 Resampler denormal guard.** The ±1e-20 alternating offset is added to every resampler input sample (the state r8brain keeps), and to both SVF state updates of the DAC filter. R-E15.

## Licensing (lead)

- **D-L1 SPEC.md is excluded from the licence check.** R-L3 quotes the two phrases it searches for, so the tracked SPEC.md would fail the check; like `docs/LICENSES.md` it only names licences. `tools/licence_check.py` builds its search strings by concatenation so it does not match itself. R-L3.
- **D-E21 Resampler transition band 15 %.** The r8brain 24-bit preset (`CDSPResampler24`) is used with a 15 % transition band instead of its 2 % default: look-ahead drops from ~34 ms to ~4.4 ms (total latency ≈ 273 samples at 48 kHz) while the passband still reaches ~20 kHz at 44.1–96 kHz, above the Mk I DAC's 16 kHz low-pass. R-E1 (preset fixed, transition band not specified).
- **D-E22 Goldens.** AC-E1.4 speaks of "the 9 non-INIT default-bank voices", but §15.3 defines eight original voices; the goldens render the nine distinct voices of slots 1–9 (INIT VOICE + the eight originals) at velocities 30/100/127, plus the 32 algorithm renders at velocity 100 — 59 streams. Each stream is 614 blocks held + 153 released (0.8004 s + 0.1993 s at 49,096 Hz) rendered by the engine with function defaults, Mk I, DAC on. The committed golden is the SHA-256 of each little-endian int32 DAC-tap stream (`tests/golden/dac_taps.sha256`), which proves bit-identity without committing 12 MB of samples. AC-E1.4, §15.3.
