# Decisions

Choices made where SPEC.md leaves room (§14) or is silent/contradictory. Each
entry: what, why, spec section.

## Engine (lead)

- **D-E1 Envelope rate formula uses ⌊qrate/4⌋.** AC-E4.1's `2^(qrate/4)` is read as `2^⌊qrate/4⌋`; only that matches R-E4's tick periods `2^(11 − (qrate >> 2))` and gate masks (the real-valued exponent would contradict R-E4). §7.1 R-E4, AC-E4.1.
- **D-E2 Hold lengths above rate 76 are not rescaled.** R-E4 says hold counts are rescaled from 44.1 kHz; AC-E4.4 requires `20 × (99 − r)` samples for rates 77 and 99. The acceptance criterion wins: only `statics[]` (rates 0–76) are rescaled by 49096/44100. Holds follow Dexed: the static rate includes the rate-scaling delta, and an attack segment to level 0 uses `statics/20`. R-E4, AC-E4.4.
- **D-E3 Attack jump at segment start.** "If L < 1716 when an attack segment begins, set L = 1716" is applied when the segment begins (not at its first tick); if the target is below 1716 the segment completes immediately, as Dexed does in the same update. R-E4.
- **D-E4 One engine-wide EG clock.** The tick counter `c` is shared by every envelope (hardware-like); in "render at host rate" a fractional accumulator issues 49096/hostRate clocks per host sample. R-E4, R-E1.
- **D-E5 Velocity reference is `velocity_data[50]` (= 240), not 239.** R-E5 writes `velocity_data[v >> 1] − 239`, which makes velocity 100 16 counts louder than KVS 0 at KVS 7; AC-E5.2 and R-E5's own "velocity 100 is the 0 dB reference" require ±1 count. The acceptance criterion wins: the reference is the table entry for velocity 100, so velocity 100 is exactly 0 at every KVS. R-E5, AC-E5.2.
- **D-E6 LFO frequency equals the Dexed `lfoSource[]` table exactly.** Dexed's `lfo.cc` multiplies the table by `4437500000·N/fs`, which runs 3.3 % faster than the Hz values in its own table (and than R-E7's "0.0625 Hz … 49.3 Hz"). AC-E7.1 requires the period within ±2 % of the table, so the ratio is `2^32·N/fs`. Everything else in `lfo.cc` is ported as is (per-instance units instead of statics). R-E7, AC-E7.1.
- **D-E7 Algorithms 4 and 6 use true chain feedback in both modes.** MSFA's `fm_core.cc` only implements self-feedback (`(flags & 0xc0) == 0xc0`), although its table marks OP4/OP5 as `FB_OUT`. R-E8's explicit "OP6←OP4 and OP6←OP5" is implemented with a per-sample loop over the chain; the feedback formula is R-E8's. R-E8.
- **D-E8 Modern carrier scaling is applied to each carrier's gain.** "Carrier 1/C as a linear multiply" is applied to the carrier operator's gain (round(65536/C)), so a carrier's feedback path sees the same level as in Mk I, where `carrierAtt` is inside the kernel. R-E14, R-E3.
- **D-E9 A masked-off operator is silent immediately in both modes** (Modern gain 0, no ramp); its envelope and phase keep running. R-E3.
- **D-E10 Controllers use integer range scaling** `cc × range / 100` instead of MSFA's float `cc × (0.01 × range)`; identical except at float rounding edges, and deterministic across platforms. R-E13.
- **D-E11 Libm-free signal path.** Detune (`exp`), MSFA's AM curve (`exp`), portamento rates and host-rate phase tables use `core/fm/detmath.h` (series built from IEEE +,−,×,÷ only), so the DAC tap is bit-identical on every OS and in WASM. MSFA's `Sin`/`Exp2` tables are generated once by MSFA's own init. §14.
- **D-E12 Idle voices.** A released voice (not held by key or sustain) becomes idle when every carrier envelope has settled at a level ≤ 512 counts (where the Mk I kernel output is exactly zero). Idle voices score +4 for allocation and are not rendered. R-E11.
- **D-E13 Portamento.** Rate is R-E12's `2100 × 2^(−0.062 × time)` semitones/s for both plain glide and glissando (Dexed's slower glissando rate is not used); glissando rounds the glide offset to the nearest semitone. Poly FOLLOW retunes voices held only by sustain to the new note and glides them there; mono FULL TIME glides from the current pitch even on non-legato notes. R-E12.
- **D-E14 Pitch bend with step.** Bend = round((bend/8192 × 12) / step) × step semitones (range treated as 12); without step `bend × range × 2^11 / 12` (MSFA). R-E6.
- **D-E15 AC-E3.3 RMS steps are checked where the Mk I output resolves them.** R-E3's operator output is 14-bit (`exptab >> shift`), and the reference test voice (algorithm 32) adds a 6-carrier attenuation of 2.58 octaves inside the kernel, so at OL < ~60 the 1 kHz tone is only a few LSB and its RMS cannot resolve ±0.05 dB. R-E3's formulas are exact (KICKOFF), so the test checks: the internal level for every OL (LUT below 20, exactly 32 counts = 0.7526 dB per step from 20 to 99), RMS steps of 0.75 ± 0.05 dB wherever the peak output is ≥ 32 LSB (OL ≥ 64), and non-decreasing RMS below. R-E3, AC-E3.3.
- **D-E16 AC-E3.1 random voices.** Carriers OL 85–99, modulators OL 40–80 (the AC allows ≤ 80), coarse 1–4, FB 0. Below OL 40 a modulator's 14-bit Mk I output has fewer than 5 bits, and its sidebands then differ from Modern's 24-bit kernel by more than 1 dB as a property of R-E3, not an error. AC-E3.1.
- **D-E17 AC-E8.2 uses OP6.** No algorithm gives OP1 a feedback loop (FB_IN is on OP2–OP6 only), so the test voice's lone sounding operator is OP6 in algorithm 32, which is that algorithm's feedback carrier. AC-E8.2.
- **D-E18 Output-stage order.** Engine output (DAC filter or `/2^27`) → resampler → master-volume gain → hard clip, so the clip is the last operation at the host rate. R-E10.
- **D-E19 Timing of MIDI and latency.** A MIDI message stamped with host sample h is applied at the start of the internal 64-sample block containing h·49096/hostRate; a block is rendered in the `render()` call in which its end passes, so results do not depend on the host block size. `latencySamples()` = one internal block at the host rate + the resampler's look-ahead (`getInLenBeforeOutStart`) + 1, or 64 without the resampler. Commands posted before `render()` are applied at its start; `render(…, 0)` returns immediately. R-E1, R-E15, AC-E1.1, AC-E15.3.
- **D-E20 Resampler denormal guard.** The ±1e-20 alternating offset is added to every resampler input sample (the state r8brain keeps), and to both SVF state updates of the DAC filter. R-E15.

## Licensing (lead)

- **D-L1 SPEC.md is excluded from the licence check.** R-L3 quotes the two phrases it searches for, so the tracked SPEC.md would fail the check; like `docs/LICENSES.md` it only names licences. `tools/licence_check.py` builds its search strings by concatenation so it does not match itself. R-L3.
- **D-E21 Resampler transition band 15 %.** The r8brain 24-bit preset (`CDSPResampler24`) is used with a 15 % transition band instead of its 2 % default: look-ahead drops from ~34 ms to ~4.4 ms (total latency ≈ 273 samples at 48 kHz) while the passband still reaches ~20 kHz at 44.1–96 kHz, above the Mk I DAC's 16 kHz low-pass. R-E1 (preset fixed, transition band not specified).
- **D-E22 Goldens.** AC-E1.4 speaks of "the 9 non-INIT default-bank voices", but §15.3 defines eight original voices; the goldens render the nine distinct voices of slots 1–9 (INIT VOICE + the eight originals) at velocities 30/100/127, plus the 32 algorithm renders at velocity 100 — 59 streams. Each stream is 614 blocks held + 153 released (0.8004 s + 0.1993 s at 49,096 Hz) rendered by the engine with function defaults, Mk I, DAC on. The committed golden is the SHA-256 of each little-endian int32 DAC-tap stream (`tests/golden/dac_taps.sha256`), which proves bit-identity without committing 12 MB of samples. AC-E1.4, §15.3.

## UI (ui/)

- **D-U1 Rejected-file notice without the brand.** §5.7 words the notice "Not a DX7 voice or bank file: ‹file name›", but R-L5 allows "DX7" in the UI only in the file-filter description and AC-L5.1 greps `ui/src` for it. The acceptance criterion wins: the notice reads "Not a voice or bank file: ‹file name›" (4 s, as specified). §5.7, R-L5, AC-L5.1.
- **D-U2 Entry points for the overlays and the voice menu.** §5 gives no box for a Settings button or a "programmer header". Settings opens from a small `SETTINGS` button at 1192, 20, 72 × 22 (above the cartridge slot, last front-panel Tab stop) and with Alt+,; the bank manager from the cartridge slot and Alt+B; the R-U3 voice menu from a `MENU` button in the header row of the voice-globals block. §5.2, §5.5, R-U3, R-U4.
- **D-U3 Typed numbers use the displayed unit only where it is a plain number.** The algorithm is typed 1–32 and detune −7…+7; every other parameter (including note names, curve/wave/mode choices, ON/OFF and master tune 0–127) is typed as its raw value, then clamped. R-U1.
- **D-U4 Digits go to a focused programmer control.** While a programmer control (spinbutton/switch) has focus, the digit keys start typed entry ("start typing", R-U1) instead of the 1/2 bend and 3–8 mod-wheel keys; note keys keep playing. Text fields (name field, the entry box) suspend the whole map as R-K2 says. R-U1, R-K1, R-K2.
- **D-U5 Drag distance is measured in window pixels** (4 px / 16 px of pointer movement per step at any zoom), not in scaled canvas pixels. R-U1.
- **D-U6 Choice and toggle controls.** Toggles (ON/OFF) and choice fields (RATIO/FIXED, POLY/MONO, porta mode, L/R curve pickers) toggle or step to the next value on a single click and on Enter; wheel, drag and typed entry work as on every control (R-U1); a double-click opens typed entry. Graph handles (EG points, break point) are pointer-only shortcuts for the numeric fields next to them, which carry focus and the ARIA names. R-U1, R-U5, §5.6.
- **D-U7 Graph axis mapping (§14 latitude).** EG and pitch-EG stages are 4 + (stage width − 4) × (99 − rate)/99 px wide with a fixed sustain segment; levels map linearly 0–99 bottom to top (pitch EG: 50 is the dashed centre line). The level-scaling graph maps break point 0–99 (A−1…C8) across the width; LIN curves rise linearly, EXP curves exponentially, − curves drawn downward and + curves upward, scaled by depth. Algorithm diagrams: a modulator sits one row above its highest target; columns are assigned depth-first from the carriers in ascending order, a parent centred over its children, a multi-target modulator centred over its targets; feedback is drawn from the FB_OUT operator to the FB_IN operator (OP4→OP6 in algorithm 4, OP5→OP6 in 6). §5.5, §5.6, §14.
- **D-U8 Output meter ballistics.** The bar rises immediately to each `meter` value and falls at 60 dB per 300 ms (the "300 ms fall"). §5.6.
- **D-U9 Tab order inside the front panel.** Wheels, sliders, NO, YES, then the mode buttons column by column (left column top to bottom, then right column, as §5.2 lists them), then buttons 1–16, 17–32, the cartridge slot and SETTINGS. Every `<button>` carries an explicit `tabindex="0"` so WebKit (macOS web view, Safari) also stops on it. R-U5.
- **D-U10 Legends.** Buttons 1–6 share one spanning violet legend "OPERATOR ON/OFF"; other legends are pre-wrapped to 7.5 px lines within the 29 px pitch. The mode buttons are drawn 44 × 16 with their legends above, because 4 rows of 26 × 36 buttons plus legends do not fit the 132 × 150 box. NO/YES carry their legends above the button ("NO · OFF · −1 · <"). ARIA names of the numbered buttons are "n EDIT-legend / FUNCTION-legend". §5.2, §14.
- **D-U11 LCD and LED rendering.** Unlit LCD dots are always drawn in `--lcd-off` (lit dots in `--lcd-ink`); `lit:false` draws only `--lcd-off`. The LED window is `--body` with unlit segments in `--led-off` and lit ones in `--led-on`. Before `snapshotEnd`, and while the web start card is shown, the LCD is unlit and the LED blank. §5.2, §5.9, §11, R-S5.
- **D-U12 Optimistic values.** A value the UI sends is shown at once; its display string `s` follows from the core's echo, which also corrects the value if the core clamps it. Continuous changes (drag, wheel, wheels, sliders) are coalesced to ≤ 1 message per animation frame per parameter, and the final value is flushed on release. R-S1, R-S6.
- **D-U13 Zoom field.** The Settings zoom list offers 50–200 % in steps of 10; "Fit" is shown only while the setting has never been set (value 0). §4.4, §5.1.
- **D-U14 Bank manager details.** The bank import choice is a dialog of its own (so a file dropped while the bank manager is closed still gets it); "Insert as cartridge" has focus, so Enter confirms it. "No reply." stays until a new request or until the bank manager closes. Eject uses the same "Replace the current cartridge? …" text and Replace/Cancel buttons as New (F-12.4 "the same confirmation"). The cartridge protect toggle stays usable without a cartridge (it mirrors the panel global). Send bank / Request dump are disabled with "MIDI output not available" when MIDI is unavailable or (web) no output is chosen, and "SysEx not permitted" without SysEx. A dropped or picked file is read up to 1 MiB + 1 byte, so the core still rejects larger files by size. §5.7, F-12, R-D4.
- **D-U15 Settings keyboard access.** While keyboard play is on, Space is sustain (R-K2), so Enter toggles the Settings checkboxes and radio buttons. The "Could not save state: ‹reason›" status line shows the latest `saveError` notice. §5.8, R-K2, F-15.
- **D-U16 Keyboard play state.** The UI uses the core's `keyboardPlay` setting once reported; before that, the build default from `env` (off for the plugin). M/F9 and the Settings checkbox send `setSetting keyboardPlay`. R-K2, §4.4, AC-K2.2.
- **D-U17 Start card.** The card covers the whole window; a click dismisses it on `click` (after the complete gesture, so no part of it reaches a control) and a key on `keydown`, with that key's `keyup` swallowed too. §5.9, AC-F1.1.
- **D-U18 Protocol addition `selectOp`.** R-U4's Alt+1…6 "select the operator" has no command in docs/PROTOCOL.md; the UI sends `{t:'selectOp', op}` (1…6), which sets the panel's selected operator like an operator edit from the programmer would (F-3) but changes nothing else. R-U4.

## Data, SysEx and state (slice A)

- **D-D1 Bit-field widths on unpack.** Bytes that hold one parameter (rates, levels, break point, depths, output level, fine, algorithm, LFO speed/delay/depths, transpose, name) are copied whole into the unpacked byte, so out-of-range values survive. Bit-field bytes are split by the parameter widths (LC/RC 2, RS 3, DET 4, AMS 2, KVS 3, MODE 1, COARSE 5, FB 3, OKS 1, LKS 1, WAVE 3, PMS 3); the bits left over are "stray" and live only in the raw packed copy. §4.6, R-D3.
- **D-D2 Packing an edited voice.** Single-field bytes keep the raw byte; bit fields are packed from effective (clamped) values so a stored voice sounds as the edit buffer did; unused bits are 0. §4.6, §4.1.
- **D-D3 Banks are kept packed.** Each bank slot is its 128 packed bytes (as in the hardware); STORE packs the edit buffer then (the raw packed copy if it is unedited since unpacking). Selecting a slot unpacks it with a valid raw packed copy, so load → select → store → export is byte-identical. §4.5, §4.6, R-D3.
- **D-D4 Outgoing SysEx data bytes are masked to 7 bits.** A headerless 4096-byte file may carry bit 7; its raw copy is kept, but a transmitted or exported dump must stay valid SysEx (the checksum covers the masked bytes). Exports and replies use device nibble 0. §4.7.
- **D-D5 File scanner.** A message runs from F0 to the next status byte; if that is F7 and the message is a 163-byte voice (`F0 43 0n 00 01 1B`) or 4104-byte bank (`F0 43 0n 09 20 00`) it is taken, any other status byte aborts it and scanning resumes there. Exactly 4096 bytes is always a headerless bank (no checksum). `vdx::sysex::scanFile()` is pure and allocation-free, for any thread. R-D4.
- **D-D6 State layout.** `docs/STATE.md`: header, a prefix with banks, cartridge, edit/stored/recall voice records (155 raw + 128 raw packed + valid flag), EDITED, voice source and function parameters, then selected memory, globals and settings, then the CRC32. The voice source is in the prefix because it belongs to the buffers (which slot the stored voice came from). The operator mask is not saved (all on after a load, R-P7). A version-1 blob must have the exact length; field values in a CRC-valid blob are clamped, not rejected. A newer-version blob loads the prefix and keeps the current values of the rest. §4.8.
- **D-D7 Loading state resets the panel** to the F-1.5 defaults (PLAY, last edit page 7 …) without starting the splash; if a Reset happens after the splash has already run (e.g. a host loads a corrupt blob into an open plugin), STATE RESET is shown at once. §4.8, F-1.
- **D-D8 New cartridge starts with its changed flag clear** — only writes set it (§4.5). Exporting does not clear it by itself; the shell sends `ClearCartridgeChanged` after a successful write (F-12.5).
- **D-D9 Export names.** Internal bank `INTERNAL.syx`; cartridge = its name, voice = the edit buffer's display name with surrounding spaces trimmed (`CARTRIDGE` / `VOICE` if empty); sanitised per F-12.5 and cut to 59 characters so name + `.syx` fit `Event::text`. The `Cartridge` event's text is NUL-terminated unless the name is 64 bytes. F-12.5, §8.
- **D-D10 Default bank JSON** uses display units (algorithm 1–32, detune −7…+7, curve/wave/mode names); slots without a file are INIT VOICE, and the generator refuses a slot 1 that is not R-P10's INIT VOICE. `make_default_bank.py --check` is a CTest. The eight voices are original programming. §15.3.
- **D-D11 Received out-of-range parameter-change values are clamped** to the parameter range (editing always writes in-range values). §4.7, §4.1.

## Front panel, MIDI and sync (slice A)

- **D-P1 YES/NO auto-repeat only repeats value steps** (EDIT/FUNCTION value pages and the naming cursor) — never dialog answers, FUNCTION confirmations, SYS INFO or TRANSMIT, so holding YES cannot run VOICE INIT. First repeat 500 ms after the press, then every 100 ms, counted in engine samples. CC96/CC97 give single steps. F-2, AC-F2.2.
- **D-P2 Data entry on a range starting above 0** (MIDI channel 1–16): value = clamp(round(pos × max), min, max) and the thumb = value/max, literally as F-2. `DataEntryPos` is emitted only for pages that have a value; elsewhere (PLAY, page 32, questions) the thumb stays. F-2.
- **D-P3 CC6/CC96/CC97 are front-panel inputs** (ignored during the splash and while a dialog is pending for CC6, they dismiss messages and answer/cancel dialogs, event source Panel) but are never transmitted, because they are received MIDI. R-M1, F-13.6.
- **D-P4 Key transpose by an armed note is a front-panel edit** (source Panel, transmitted while AVAIL); the swallowed note's note-off is swallowed too. Entering EDIT on page 31 with the EDIT button, or showing it from the programmer, does not arm; starting COMPARE disarms. F-5.
- **D-P5 Transmit.** Every changed parameter of a front-panel or programmer edit is sent, including multi-byte edits (EG copy, paste, swap, randomise, naming); voice loads (selection, VOICE INIT, EDIT RECALL, dumps, file loads, STORE) are not edits and are not sent. Throttle per parameter: sent at once if ≥ 10 ms since that parameter's last message, otherwise marked and sent (with the then-current value) when 10 ms have passed. Turning SYS INFO off drops pending messages and moves FUNCTION 8 from TRANSMIT to SYS INFO. F-13.6, AC-M3.1.
- **D-P6 External changes that do not change the value do nothing** — in particular they do not end COMPARE — so a host re-sending unchanged automation cannot cancel COMPARE. R-S2, F-9.4.
- **D-P7 Programmer menu operations** (paste/init operator, swap, EG copy, Init voice, Randomise) cancel dialogs and naming and end COMPARE, but do not switch the panel mode or the selected operator: they are not F-3 value changes. A programmer change of the operator mask from PLAY/FUNCTION goes to EDIT on the last edit page (the mask has no page). Programmer edits during the splash change state but not the panel mode. F-3, R-U2, R-U3, F-1.4.
- **D-P8 Voice-menu Compare** from PLAY/FUNCTION enters EDIT and starts COMPARE; it does nothing while CLEAN. R-U3.
- **D-P9 MEMORY SELECT CRT without a cartridge in EDIT keeps COMPARE running.** F-2's cell ("NOT READY, nothing else changes") is more specific than F-9.4 ("MEMORY SELECT … ends COMPARE"). Conflict resolved for F-2. F-2, F-9.
- **D-P10 EG copy to a different operator always sets EDITED** (F-8.2), even if the EG bytes were already equal; R-P4 ("any change to the bytes") is the general rule, F-8 the specific one. Conflict resolved for F-8. F-8, R-P4.
- **D-P11 OPERATOR SELECT still works while comparing** (F-9.2 lists only numbered buttons, YES/NO and data entry); the LCD keeps the PLAY page until COMPARE ends. F-9.
- **D-P12 Bank-manager selection, file loads (voice or bank), bank-manager copies and SysEx dumps cancel a pending dialog**; a loaded or received single voice also ends naming (EDIT, VOICE NAME page). §8, F-4.4.
- **D-P13 After the splash the selected memory is the voice source's bank, or INT** if that bank is CRT and no cartridge is present (it can only be selected with a cartridge). Messages raised during the splash are dropped (the splash owns the LCD); notices are still emitted. F-1.5, F-1.4.
- **D-P14 Value strings (R-P8).** One module (`core/panel/format.h`) builds every LCD field; the canonical string is the field trimmed. Choices: oscillator mode `FREQUENCY(RATIO)` / `FIXED FREQ.(Hz)`; coarse and fine show the computed ratio/frequency (as their LCD pages); the operator-mask event text is the six LCD digits, host operator switches `ON`/`OFF`; assign bytes give `PITCH AMP EG-BIAS` as e.g. `ON OFF OFF` (each bit's page shows one); SYS INFO `AVAIL`/`UNAVAIL`; master tune one decimal, rounded half away from zero, no sign at zero (`0.0 cents`, `+73.8 cents`, `-75.0 cents`); `LfoHz` is MSFA `lfoSource[]` rounded to hundredths (`5.62 Hz`); a name character's string keeps a space. §5.3, §4.9, R-P8.
- **D-P15 Meters** are dBFS × 100 relative to 2^27 (the engine's output scale for an operator's Q24 peak), clamped to −6000…0, at ⌈rate/30⌉-sample intervals; consecutive all-silent meter events are suppressed. `log10` is used for display only. §5.6.
- **D-P16 Randomise** uses xorshift32; a command with seed ≠ 0 reseeds, seed 0 continues the sequence (tests: seed 1 then 0s). Coarse is drawn from {0, 1, 1, 1, 2, 2, 2, 3, 4, 5, 6, 7, 8}. R-U3.
- **D-P17 Event sources.** Parameter events carry the command's source; front-panel changes are Panel, received MIDI is Midi (notes, CC5, CC7, program change) or SysEx, timer-driven changes (end of splash, auto-repeat) are Internal/Panel, a snapshot is State. `PanelState.page` is 0 in PLAY and during the splash; the LCD `lit` field is always 1 (the web start card is a shell state). vdx.h, R-S4, R-S5.
- **D-P18 Keyboard play defaults to on in the core** (standalone, web); the plugin shell sets it off for a new instance. `ReleaseAll` also releases a sustain that the computer keyboard turned on. §4.4, R-K2.
- **D-P19 Protected and received dumps are reported to the bank manager:** a MIDI bank refused by internal protect emits `Notice kNoticeProtected`, accepted dumps emit `kNoticeDumpReceived` (b = 0 voice, 1 bank), Send bank / FUNCTION 8 TRANSMIT emit `kNoticeCompleted` and show ` COMPLETED`. F-12.6, F-12.7, F-13.
